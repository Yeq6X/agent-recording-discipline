# AI秘書エージェント記録作法

複数のAIエージェントに仕事を頼む人のための、「記録の置き方」の一式です。

## 思想

> 記録を特定のアプリに閉じ込めない。

メモリ層（記録）とエージェント層（働き手）を分離します。記録がこのフォルダ（＝gitリポジトリ）に残っていれば、昨日のエージェントの仕事の続きを、今日は別のエージェントにそのまま渡せます。エージェントは交換可能、記録は使い続けるほど価値が増す資産になります。

## セットアップ（5分）

ノートがまだ何もない状態から始められます。最初のノートやメモリは、エージェントとの対話で作ります（手順は `START.md`）。

1. このフォルダをコピー（または `git clone`）して、自分の好きな場所に置く
2. Obsidianで開く場合は、このフォルダをそのまま vault として開く（任意）
3. エージェントにこう指示する：

> このリポジトリの `AGENTS.md` と `guide.md` を読んで、それに従って作業して。

コーディングエージェントの中には `AGENTS.md`（Claude Codeは `CLAUDE.md` 経由）を自動で読むものがあり、その場合はcloneした直後から作法に沿って動き始めます。チャット型のエージェントには上の一文を渡してください。

## 中身

| ファイル | 役割 |
|---|---|
| `START.md` | ノートゼロからの始め方（初回セットアップの手順） |
| `AGENTS.md` | エージェントが従う作業規約（本体） |
| `guide.md` | 記録作法の解説（背景・理由・注意点の蓄積） |
| `work.json` | 作業表の実体（`scripts/work.py` が読み書きする） |
| `scripts/work.py` | 作業表CLI（サーバ不要・Python標準ライブラリのみ） |
| `notes/` | 話題別ノート（frontmatter付きmarkdown） |
| `memory/` | 共有メモリ（プロジェクト情報・運用ルール・好み） |

## 作業表の使い方（エージェントが使う）

```bash
python scripts/work.py new --session claude:main "タイトル"   # 着手前に登録
python scripts/work.py progress --session claude:main <id> "やったこと"
python scripts/work.py done --session claude:main --result "結果" --notes <ノートid> <id>
python scripts/work.py list
```

セッション名は `<エージェント>:<スレッド>` の形（例：`claude:main`、`codex:main`）。誰が何をしているかが常に作業表で見えることが、この作法の核です。

## 段階（無理に全部やらなくていい）

- **Lv1 規約だけ** — `AGENTS.md` と `guide.md` をエージェントに読ませるだけ。道具は最小限
- **Lv2 ローカル作業表** — このキットの状態。作業表スクリプトで複数エージェントの作業を可視化
- **Lv3 強制と同期** — hookで記録を強制したり、クラウドに正本を置いて複数マシン・遠隔エージェントから即時共有（発展形）

## ライセンス・由来

実運用で育てた作法を、誰でも始められる形に切り出したものです。自由に改変・再配布してください。作法の細部は `guide.md` の更新履歴とともに育てていく前提です。
